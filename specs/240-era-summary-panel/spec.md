# Feature Specification: 年代サマリーパネル

**Feature Branch**: `240-era-summary-panel`
**Created**: 2026-05-06
**Status**: Draft
**Input**: User description: "issue #138 の『2. 年代サマリーパネル』を実現したい — 地図の利用者として、年代を選んだときに同時代の世界の状況（横のつながり）を一目で把握したい"
**Source Issue**: [#138](https://github.com/akihiro-tj/world-history-map/issues/138)

## 背景と目的

### 背景

世界史の学習における「横のつながり」（同時代の地域間関係）の理解は、本プロダクトが解決すべき主要課題のひとつである。現状の世界史地図は、各領土を個別にクリックすることで詳細情報（時代背景・主要イベント等）を確認できるが、ある年代の「世界全体で何が同時に起きていたか」を俯瞰する手段がない。利用者は同時代の世界像を組み立てるために、領土を 1 つずつクリックして情報を読み比べる必要がある。

### 目的

選択中の年代における世界の概況を、地図と並行して俯瞰できる「年代サマリーパネル」を提供する。これにより、個別領土へのクリックを介さずに、同時代の世界像を即座に把握できる学習動線を実現する。

### スコープの限定

issue #138 では「ホバーツールチップ」と「年代サマリーパネル」の 2 つの解決策が併記されているが、本仕様は **後者のみ** を扱う。ホバーツールチップは独立した機能として別途扱う。

## Clarifications

### Session 2026-05-07

- Q: サマリーを提供する年代のカバレッジは？ → A: 全年代に提供（`historical-basemaps` の対応年すべてに整備する）
- Q: サマリーパネルの初期表示状態は？ → A: デスクトップは開いてスタート／モバイルは閉じてスタート（デバイス別差別化）
- Q: モバイルでの「退避」の具体的な振る舞いは？ → A: 完全に閉じる（再表示は開閉ボタンによる明示操作）
- Q: サマリー内参照（領土名・年代へのリンク）の必須性は？ → A: 任意。データ整備ガイドラインで「主要な領土・年代には参照を付ける」を努力義務として明示する
- Q: アクセシビリティ要件の最低ラインをどう記述しますか？ → A: 既存パネル（license-disclaimer 等）と同等の最低ライン（キーボード操作可・状態のスクリーンリーダー認識・参照リンクは標準操作で活性化可）を明文化する

### Session 2026-05-07 (v2 design mock review)

デザインモック v2 の検証によって得られた決定：

- Q: territory-info-panel との共存ルールを再検討するか？ → A: **全デバイスで後勝ち排他に統一**。v1 の「デスクトップ並列同時表示／モバイル後勝ち排他」を廃止し、デバイスを問わず後勝ち排他に統一する。状態数が減り、操作モデルが一貫する
- Q: 領土詳細パネルからサマリーパネルへスムーズに戻れるようにするか？ → A: **領土詳細パネル内に中立文言の遷移帯を常時表示**。「{year} 年の世界を見る」のテキストを、遷移元（サマリー / 地図）に依存しない中立文言として領土詳細パネル上端に配置。「← 戻る」ではなく「サマリー側に切り替える」意図を表現
- Q: 領土詳細パネル内の閉じるボタン位置は？ → A: パネル右上（dialog / sheet の慣習に従う）。遷移帯と同じ行の右端に配置し、サイズと形で視覚階層を分ける

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同時代の世界概況を俯瞰する (Priority: P1)

利用者として、年代を選択したときに、その年代の世界全体の概況（主要な文明・帝国・地域動向）を一覧で把握したい。これにより、地図上の各領土を個別にクリックせずとも、同時代に世界で何が起きていたかを最短動線で理解できる。

**Why this priority**: 本機能の中核価値であり、これがなければ「横のつながりの俯瞰」というプロダクト価値が成立しない。MVP の最小単位はこの俯瞰ビュー。

**Independent Test**: 年代を選択した状態でサマリーパネルを開き、その年代の世界概況が読める。年代を切り替えるとサマリー内容も更新されることを確認できれば、俯瞰の価値を提供できる。

**Acceptance Scenarios**:

1. **Given** アプリケーションを開いた状態, **When** 年代サマリーパネルを開く, **Then** 現在選択中の年代における世界概況のサマリーが表示される
2. **Given** サマリーパネルが表示されている状態, **When** 年代セレクターで別の年代に切り替える, **Then** サマリーパネルの内容が新しい年代の概況に更新される

---

### User Story 2 - パネルの開閉とレイアウト共存 (Priority: P2)

利用者として、サマリーパネルを必要なときだけ表示し、地図操作の邪魔にならないようにしたい。また、個別領土の詳細パネル（既存の territory-info-panel）との関係性が明確で、同時に閲覧しても混乱しないようにしたい。

**Why this priority**: 俯瞰ビューが地図閲覧を阻害しては本末転倒。既存パネルとの共存ルールが曖昧だと UX が破綻する。P1 の価値を実用レベルにするための土台。

**Independent Test**: パネルを開閉する操作が提供されており、地図やその他既存パネルが正常に動作することを確認できる。

**Acceptance Scenarios**:

1. **Given** 地図が表示されている状態, **When** サマリーパネルの開閉操作を行う, **Then** パネルが表示／非表示に切り替わる
2. **Given** サマリーパネルが表示されている状態, **When** 地図をズーム・パンする, **Then** 地図操作は阻害されず、パネル内容も維持される
3. **Given** デスクトップまたはモバイルでサマリーパネルが表示されている状態, **When** 領土詳細パネル（territory-info-panel）を開く, **Then** 後から開かれた領土詳細パネルが優先表示され、サマリーパネルは完全に閉じられる（後勝ち排他、全デバイス共通）
4. **Given** 領土詳細パネルが表示されている状態, **When** パネル内のサマリー遷移帯（「{year} 年の世界を見る」）を選択する, **Then** 領土詳細パネルが閉じ、サマリーパネルが開く（操作 1 回でサマリーへ復帰可能）
5. **Given** モバイルデバイスで利用している状態, **When** サマリーパネルを開く, **Then** 地図の主要部分が視認できる範囲でパネルが表示される

---

### User Story 3 - サマリーから個別領土への動線 (Priority: P3)

利用者として、サマリー内で気になった領土・出来事から、地図上の該当領土または個別の詳細パネルへ遷移したい。これにより「俯瞰 → 詳細」という自然な学習フローが成立する。

**Why this priority**: P1 と P2 で俯瞰ビュー単独の価値は成立する。詳細への動線はあると体験が滑らかになるが、無くても俯瞰ビュー単独で価値がある。

**Independent Test**: サマリー内に領土名や年代の参照がある場合、それをクリック／タップすると地図のフォーカス移動または領土詳細表示につながることを確認できる。

**Acceptance Scenarios**:

1. **Given** サマリーパネルが表示されている状態, **When** サマリー内の領土名をクリック／タップする, **Then** 該当領土が地図上で強調表示される、またはその領土の詳細パネルが開く（後勝ち排他によりサマリーパネルは閉じる）
2. **Given** サマリーパネルが表示されている状態, **When** サマリー内に別の年代への参照（リンク）がある場合にクリック／タップする, **Then** 地図がその年代に切り替わり、サマリー内容も追従する
3. **Given** 領土詳細パネルが表示されている状態, **When** パネル内のサマリー遷移帯を選択する, **Then** サマリーパネルへ戻り、利用者は「俯瞰 → 詳細 → 俯瞰」の往復を 1 タップずつで行える

---

### Edge Cases

- 選択された年代に対するサマリーデータが存在しない場合（例：未生成の年代、極端に古い／未来の年代）、利用者にどう伝えるか
- サマリー本文が長大になった場合の可読性（スクロール、要約の階層化）
- 領土詳細パネル表示中に年代セレクターで年代を切り替えた場合、領土詳細の内容と遷移帯の年代表記（FR-011）がどのように更新されるか
- ネットワーク遅延・データ取得失敗時の挙動（ローディング表示、フォールバック）
- 画面サイズが極端に小さい（横幅 320px 程度のモバイル）／大きい（4K デスクトップ）デバイスでの表示崩れ

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、選択中の年代に対応する「世界の概況」を年代サマリーパネルとして閲覧できる
- **FR-002**: 年代セレクターで年代が変更されたとき、サマリーパネルの内容は変更後の年代の概況に追従して更新される
- **FR-003**: 利用者は、サマリーパネルを開閉する明示的な操作を行える。アプリケーション起動時の初期表示状態はデバイスに応じて分かれる：
  - デスクトップ：開いた状態でスタート（俯瞰価値の即時提供）
  - モバイル：閉じた状態でスタート（地図領域の確保）
- **FR-004**: サマリー内容は **地域別カード形式** で構成される。地理的に区切られた地域（例：ヨーロッパ／東アジア／南アジア／中東・北アフリカ／サブサハラ・アフリカ／南北アメリカ／オセアニア など）ごとに見出しと 1〜2 文程度の概況を提示する。地域区分の具体的な集合と粒度は plan フェーズで確定する
- **FR-005**: サマリーデータは **年代単位の専用データセット** として整備される。既存の領土別 description（`descriptions/{year}.json`）とは独立した、年代を主キーとするデータが提供される。生成は事前にオフラインで行い、アプリケーションには静的データとして同梱される（既存の description と同じ運用モデル）
- **FR-006**: サマリーパネルと既存の領土詳細パネル（territory-info-panel）は **全デバイスで後勝ち排他** で動作する。後から開かれたパネルが優先表示され、もう一方は完全に閉じられる。デスクトップ・モバイル間で挙動を分けない
- **FR-007**: 選択中の年代に対するサマリーデータが存在しない場合、利用者に「未提供である」旨が伝わる表示が行われる
- **FR-008**: サマリーパネルの表示は地図操作（ズーム・パン・領土クリック）を阻害しない
- **FR-009**: サマリー内に領土名・年代への参照が含まれる場合、それらは利用者の遷移操作に応答可能な要素として提供される（領土ハイライト／詳細表示／年代切替）。参照の付与は **任意** であり、データ整備ガイドラインにて「主要な領土・年代には参照を付ける」ことを努力義務として明示する（全カードで必須とはしない）
- **FR-010**: サマリーパネルは既存パネル（`license-disclaimer` 等）と同等のアクセシビリティ最低ラインを満たす：
  - キーボードのみで開閉・スクロール・参照リンクの活性化が可能
  - パネルの開閉状態（開／閉）がスクリーンリーダーで認識可能（`aria-*` 等を通じて状態が伝わる）
  - 参照リンクは標準的な活性化操作（Enter／Space／クリック／タップ）で機能する
- **FR-011**: 領土詳細パネル（territory-info-panel）が表示されている間、利用者は **常にサマリーパネルへ 1 操作で遷移できる**。具体的には領土詳細パネル内に遷移導線が常時表示される：
  - 文言は **遷移元（サマリー / 地図）に依存しない中立表現**（例：「{year} 年の世界を見る」）
  - 遷移操作で領土詳細パネルが閉じ、サマリーパネルが開く（後勝ち排他のルールに従う）
  - 導線は領土詳細パネルが開いている全状況で表示される（地図上の領土を直接タップして開いた場合も含む）
  - 「閉じる」操作との視覚的な区別が明確であり、利用者が両者を混同しない

### Key Entities *(include if feature involves data)*

- **EraSummary（年代サマリー）**: ある年代における世界全体の概況。対象年（year）と複数の地域カード（regions）の集合を持つ
- **RegionCard（地域カード）**: EraSummary を構成する単位。地域識別子（region）、表示見出し（title）、1〜2 文の概況本文（context）を持つ。サマリー本文中の領土名・年代への参照は本カード内に含まれる
- **EraSummaryReference（参照）**: 地域カード本文中から地図上の領土または別の年代へ遷移するための論理的な参照単位。少なくとも遷移種別（領土／年代）と対象識別子を持つ
- **TerritoryDescription（既存・参照）**: 既存の領土別データ（`descriptions/{year}.json`）。本機能では直接のデータソースとはせず、サマリー内参照（領土遷移）の解決対象として利用される

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 任意の年代を選択した利用者が、地図上の領土を個別にクリックせず、サマリーパネルを開く操作 1 回のみで「同時代に世界で起きていたこと」の主要な要素（地域・主要勢力・代表的な出来事のいずれか）を読み取れる
- **SC-002**: 年代セレクターで年代を切り替えてからサマリー内容が更新されるまで、利用者が体感する待ち時間は通常のネットワーク環境下で 1 秒以内に収まる
- **SC-003**: 既存機能（地図のズーム・パン、年代選択、領土クリック）の操作性に対する後退（regression）が発生しない
- **SC-004**: モバイル（縦持ち、横幅 360px 程度）とデスクトップ（横幅 1280px 以上）の両方で、サマリーパネル表示時に地図の中央領域が視認できる状態が維持される
- **SC-005**: 同時代の世界像を理解するために必要な操作回数が、現状（領土を個別クリックして情報収集する動線）と比較して有意に減少する（同等の理解を得るためのクリック数の削減で評価）

## Assumptions

- 年代サマリーは既存の `descriptions/{year}.json` とは独立した、年代を主キーとする専用データとして整備される
- サマリーの初版はあらかじめ生成済みの静的データとしてアプリケーションに同梱され、ランタイムで AI 推論を行う方式は採用しない（既存の領土説明と同じ運用モデルを踏襲）
- 地域区分（カードの集合と粒度）は世界史の俯瞰に適した一定の集合に揃える（例：ヨーロッパ／東アジア／南アジア／中東・北アフリカ／サブサハラ・アフリカ／南北アメリカ／オセアニア など）。具体的な区分は plan フェーズで確定する
- 提供される年代の集合は、既存の地図データ（`historical-basemaps`）が対応する **全年代** に揃える。FR-007（未提供時の表示）は欠損が生じた場合のセーフネットとして機能し、原則すべての年代でサマリーが表示されることを期待値とする（新規年代の追加は本仕様の範囲外）

## Out of Scope

- ホバー時のツールチップ表示（issue #138 の「1. ホバーツールチップ」は本仕様の対象外）
- AI による実行時生成（ランタイム LLM 呼び出し）
- サマリー内容の利用者編集機能・コメント機能・共有機能
- 多言語対応（日本語以外の言語でのサマリー提供）
- サマリーの自動更新パイプライン整備（データ生成のオフライン手順は plan で扱うが、CI/CD 自動化は対象外）

## Dependencies

- 既存の年代選択機能（year-selector）— サマリーの「対象年」を決定するソース
- 既存の領土別 description データ（`descriptions/{year}.json`）— サマリー素材としての参照可能性
- 既存の領土詳細パネル（territory-info-panel）— 後勝ち排他の対象であり、サマリーへの遷移帯（FR-011）を追加する改修対象
