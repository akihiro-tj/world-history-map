# Feature Specification: Camera Fit on Territory Select

**Feature Branch**: `241-camera-fit-on-territory-select`  
**Created**: 2026-05-10  
**Status**: Draft  
**Input**: GitHub Issue #257 — 領土選択時にパネルで隠れない位置へカメラを移動する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Desktop で選択した領土が情報パネルに隠れない (Priority: P1)

世界地図のユーザーが Desktop（左側に固定された情報パネルが表示される画面サイズ）で地図上の領土をクリックしたとき、選択した領土が情報パネルの背後に隠れず、見える位置にカメラが移動する。

**Why this priority**: 本機能の核となる課題。Desktop では西ヨーロッパや北アフリカなど画面左側の領土をクリックすると `TerritoryInfoPanel` で完全に隠れ、ハイライトや形状の確認ができない。これが解決されなければ、領土を選んでも何が選ばれたか視覚的に把握できないため、地図学習体験そのものが成立しない。

**Independent Test**: Desktop ビューポート（幅 1024px 以上）で「ハイライトしたら隠れる位置にある領土」（例: 1600 年のフランス）をクリックし、選択ハイライトがパネルに重ならない領域に表示されること、ユーザーが手動で地図をパンせずに領土を視認できることを確認する。

**Acceptance Scenarios**:

1. **Given** Desktop ビューポートで地図が表示されている、 **When** 画面左側に位置する領土（例: フランス、スペイン）をクリックする、 **Then** カメラが移動し、選択された領土のハイライトが情報パネルに重ならない領域内に完全に収まる。
2. **Given** Desktop ビューポートで地図が表示されている、 **When** 画面右側に位置する領土（例: 中国、日本）をクリックする、 **Then** 選択された領土が情報パネルに重ならない領域内に表示され、カメラ移動が発生しても領土の視認性が損なわれない。
3. **Given** ある領土が選択されパネルが開いている、 **When** 別の領土をクリックする、 **Then** カメラが新しい領土に合わせて再調整され、新しい領土が情報パネルに重ならない領域に表示される。

---

### User Story 2 - Mobile で選択した領土が BottomSheet に隠れない (Priority: P1)

Mobile 端末のユーザーが領土をタップしたとき、選択した領土が画面下部の BottomSheet の背後に隠れず、シートより上の領域に表示される。

**Why this priority**: Mobile では BottomSheet が画面下部の半分前後を占有することがあり、南半球（オーストラリア・南米南部・南アフリカなど）の領土が完全に隠れる。Desktop と同じく、選んだ領土が見えなければ機能として成立しないため P1。

**Independent Test**: Mobile ビューポート（幅 768px 未満）で南半球の領土をタップし、選択ハイライトが BottomSheet に重ならない上部領域に完全に表示されることを確認する。BottomSheet の展開サイズが変わっても可視性が保たれることを併せて検証する。

**Acceptance Scenarios**:

1. **Given** Mobile ビューポートで地図が表示されている、 **When** 画面下部に位置する領土（例: オーストラリア、アルゼンチン）をタップする、 **Then** カメラが移動し、選択された領土が BottomSheet で覆われていない上部領域内に完全に収まる。
2. **Given** Mobile で領土が選択され BottomSheet が開いている、 **When** BottomSheet の高さがユーザー操作で変化する、 **Then** 直前の選択操作によって決まったカメラ位置はそのまま維持される（BottomSheet 高さの変化自体は再フィットを発火しない）。

---

### User Story 3 - クリック以外の経路で選択した領土も同じ振る舞い (Priority: P2)

ユーザーが地図クリック以外の手段（年代概要パネルからの遷移、`SummaryNavStrip` を通じたナビゲーションなど）で領土を選択したときも、地図クリック時と同じく自動でカメラが領土に合うよう移動する。

**Why this priority**: クリックと非クリックで挙動が異なると、ユーザーは「なぜ今は移動しないのか」を毎回学習し直す必要があり、UI の予測可能性が損なわれる。ただし主要な選択経路は地図クリックであるため、最重要シナリオの後段として P2 に位置付ける。

**Independent Test**: 年代概要パネルなど、地図上のクリック以外で領土を選択する経路を 1 つ実行し、地図クリック時と同等にカメラがフィットすることを確認する。

**Acceptance Scenarios**:

1. **Given** 領土が未選択の状態、 **When** ユーザーが地図上のクリック以外の方法で領土を選択する、 **Then** カメラが選択された領土に合わせて自動的に移動し、領土が情報パネルで隠れない位置に表示される。

---

### User Story 4 - パネルを閉じてもカメラは戻らない (Priority: P3)

ユーザーが情報パネルを閉じたとき、カメラの位置・ズームは選択時に移動した状態のまま維持され、選択前の位置には戻らない。

**Why this priority**: 選択した領土を起点にユーザーがさらに周辺を探索することを支える挙動で、一般的な地図 UI の規範と整合する。視認性の確保（P1）が達成されていれば、戻し処理がなくても致命的な問題は起きないため P3。

**Independent Test**: 領土を選択してカメラが移動した後、情報パネルを閉じ、カメラ位置・ズームが選択時の値から変化しないことを確認する。

**Acceptance Scenarios**:

1. **Given** ある領土が選択され、それに合わせてカメラが移動している、 **When** ユーザーが情報パネルを閉じる、 **Then** カメラの中心位置とズームレベルは閉じる直前の状態のまま維持される。

---

### Edge Cases

- **極端に小さな領土**（都市国家、島嶼国など）を選択した場合、最大ズームに達してしまい周囲の地理的文脈が失われないよう、ズームインに上限を設ける必要がある。
- **極端に大きな領土**（モンゴル帝国、ロシア帝国など、ほぼ全画面を覆う領土）を選択した場合は、領土全体を可能な範囲で表示し、最低限の余白を確保する。
- **日付変更線をまたぐ領土**（ロシア、太平洋諸島など）を選択した場合も、領土が分断されて見えないよう適切に収まる位置にカメラが調整される。
- **同じ領土を選択した状態のまま年代を切り替えた**結果、領土の形状が変化した場合、変化後の形状に合わせて再フィットが発火する。
- 同じく**年代切り替えで選択中の領土がその年代に存在しなくなった**場合、選択は解除され、カメラ移動は発火しない。
- ユーザーが連続して別の領土を素早くクリックした場合、最後の選択に対応するカメラ位置に収束し、途中のフィット処理が中途半端な位置でとどまることはない。
- ビューポートサイズが Desktop / Mobile の境界をまたいで変化した（リサイズ、画面回転など）場合、情報パネルのレイアウトが切り替わるが、すでに完了したフィット処理を遡って再計算する必要はない（次回の選択時に新しいレイアウトで再計算される）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 領土が新しく選択されたとき、システムは選択された領土が情報パネル（Desktop の固定パネル / Mobile の BottomSheet）に重ならない可視領域内に完全に収まるよう、地図の中心とズームを自動調整しなければならない。
- **FR-002**: フィット処理は、Desktop（左側パネル）と Mobile（下部 BottomSheet）でそれぞれ実際にパネルが占有する領域を除いた可視矩形を基準に動作しなければならない。
- **FR-003**: 小さい領土を選択した場合、システムは過度にズームインしないよう、選択時に許容する最大ズームレベルに上限を設けなければならない。
- **FR-004**: 大きい領土を選択した場合、システムは領土全体が可視領域に収まるようズームアウトし、領土が画面外にはみ出さないようにしなければならない。
- **FR-005**: フィット処理は選択経路（地図クリック、ナビゲーション UI、その他のプログラム的な選択操作）に依存せず、選択状態の変化を契機に等しく発火しなければならない。
- **FR-006**: ユーザーが情報パネルを閉じた場合、システムはカメラ位置・ズームを選択時に移動した状態のまま維持しなければならず、選択前の位置に戻してはならない。
- **FR-007**: カメラの移動はユーザーが空間的な連続性を失わないよう、即座のジャンプではなくアニメーション付きの遷移として実現しなければならない。
- **FR-008**: 選択中の領土が年代切り替えによって形状を変化させた場合、システムは新しい形状に合わせてカメラを再フィットしなければならない。
- **FR-009**: BottomSheet の展開サイズの変化（ユーザーがシートを引き上げる/縮める操作）はカメラの再フィットを発火させてはならない。
- **FR-010**: 連続した領土選択操作が発生した場合、システムは最後の選択に対するフィット結果のみが最終的なカメラ状態として残るよう、競合を解消しなければならない。

### Key Entities

- **Selected Territory**: 現在ユーザーが選択している領土。地図上に表示されるハイライト形状（多角形）と関連付けられ、選択経路（クリック/ナビゲーション）に依存しない統一的な状態として扱われる。
- **Visible Map Area**: 情報パネルに占有されていない、地図表示の可視矩形領域。Desktop ビューポートでは左端からパネル幅と外周マージンを除いた領域、Mobile ビューポートでは BottomSheet の上端より上の領域として定義される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用可能な全年代・全領土から無作為抽出した 100 件の領土選択について、選択直後に対象領土のハイライトが情報パネルに重ならない可視領域に完全に表示される割合が 100% である。
- **SC-002**: 領土選択後にユーザーが対象領土を視認するために手動で地図をパンする必要がある割合が 5% 未満である（ユーザーテストまたは UI スナップショット検証で計測）。
- **SC-003**: 選択操作からカメラの移動が完了するまでの時間が 800 ミリ秒以内である。
- **SC-004**: 情報パネルを閉じる操作によってカメラが移動する不具合が発生する頻度が 0 件である（パネルを閉じた直後の中心座標・ズームが、閉じる直前の値と一致することを自動検証）。
- **SC-005**: Desktop / Mobile 双方のレイアウトについて、上記 SC-001〜SC-004 の指標を独立して達成する。

## Assumptions

- カメラの移動は選択状態の変化を契機にする。年代変化単独（同一領土の形状更新時を除く）や情報パネルの開閉自体は契機にしない。
- 「情報パネルに重ならない可視領域」の判定は、Desktop ではパネルの占有矩形（左上固定、幅約 384px 相当 + 外周マージン）、Mobile では BottomSheet の表示領域を基準とする。具体的な余白の数値は実装フェーズでの調整事項とする。
- 最大ズームの上限は「対象領土の周囲の地理的文脈（隣接国・海岸線など）が把握できる程度」を基準とし、具体的な値は実装フェーズで決定する。
- アニメーション付き遷移はカメラ位置の連続性を保つ目的のみのもので、装飾的な演出（イージング曲線の差別化など）は本機能の対象外とする。
- 本機能は `TerritoryInfoPanel` のみを対象とし、`EraSummaryPanel` 表示中のカメラ挙動は変更しない。

## Out of Scope

- 情報パネルを閉じた際にカメラを選択前の位置へ戻す挙動（明示的に対象外）。
- 年代変更時にハイライト中の領土が消えた場合のカメラ自動復帰（選択解除のみで、カメラは移動しない）。
- ハイライトされた領土の中心点インジケータ表示などの付随的な視覚演出。
- BottomSheet のサイズ変化に追随したリアルタイムな再フィット。
- マウスホバーやキーボード操作での仮選択に対するカメラ移動。
